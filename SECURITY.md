# Security Policy

Do not submit secrets, real host addresses, private inventory, keys, logs, or
personal data in issues or pull requests. Use synthetic, minimized examples.

Until a private reporting channel is configured, open a minimal GitHub issue
that identifies the affected component without exploit details or sensitive
data, and request private coordination from the maintainer.

Read-only skills must not mutate a target as a side effect. Mutating workflows
must require explicit scope, target verification, rollback, and backup evidence.
Only the latest tagged release is supported during the experimental phase.
